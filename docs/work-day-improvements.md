# Work days — running improvements list

**Status:** Living doc / proto-requirements · started 2026-07-26

The home for feedback and improvement ideas about our **in-person work days** —
the Sensemaking Sprint and the Hackathon. This is the *events* counterpart to
[`feedback-running-list.md`](feedback-running-list.md) (which tracks feedback on
the app itself). Entries here are deliberately rough: observations from running
the days, ideas for the next one, and open questions.

**Why this lives in the repo:** the work days are the manual, in-person
prototype of what OLOS digitizes. The Sensemaking Sprint is the physical
version of the member sensemaking journey in
[`SENSEMAKING_FLOW.md`](SENSEMAKING_FLOW.md) (observations → stakeholder
mapping → patterns → paradoxes), and the Hackathon maps to the Build Cycle's
solution/build phases. What we learn running these days by hand is
proto-requirements for the product. When an item here matures into something
buildable, graduate it: app-scoped fixes go to
[`feedback-running-list.md`](feedback-running-list.md), fuller specs get a doc
in [`requirements/`](requirements/).

## How to add an entry

Same discipline as the app feedback list — add a row (next number, today's
date), and a `### N — Title (date)` section under **Details** if there's more
to say. Cover:

1. **What you observed** — concrete moment from the day, or a concrete idea
   for the next one.
2. **Which event / phase** — sensemaking, hackathon, or both; and where in the
   day (arrival, group formation, the exercise itself, share-out, wrap-up…).
3. **Needs more thought?** — clear-cut change vs. needs design/facilitation
   judgement.
4. **Product-relevant?** — does this imply something OLOS should eventually
   do/support (i.e. is it a proto-requirement), or is it purely event ops?
5. **Who's submitting.**

## Standing questions for every retro

Prompts to run through after each work day — delete or replace as we learn
which ones earn their keep:

- **The bridge to the product:** did anything produced on paper/stickies get
  lost because there was no obvious place to put it in OLOS afterward? (This
  is the intake `SENSEMAKING_FLOW.md` cares about.)
- **The bridge between the two days:** does the Sensemaking Sprint's output
  (paradoxes, framed problems) actually arrive at the Hackathon as usable
  input, or do hackathon teams start from scratch?
- **Arrival → productive:** how long from doors-open to everyone actively
  working? What ate that time?
- **Facilitation load:** what did hosts have to improvise or repeat-explain?
  Those are candidates for printed material, signage, or product support.
- **Who struggled:** first-timers vs. returners — where did each group stall?
- **What we'd cut:** if the day were an hour shorter, what goes?
