## 1. The platform in one paragraph (the team's own words)

The near-term identity: **"OLOS is the build-cycle operating system for The Upskilling Labs… it walks members through a Build Cycle — from field observations to formed pods to shipped projects… It replaces a battery of Google Forms and reconciliation spreadsheets with one tool"** [FACT: README.md:3-8]. The organizing principle: **"The Labs runs like open source"** — a *Sector* is "the durable community around a problem domain," a *Cycle* is "a time-boxed cohort that incubates new projects and people into that sector," and graduated projects live on under MIT/CC-BY commons governance [FACT: docs/SECTOR_MODEL.md:35-59]. The long-term identity is Project Ortelius, the "Living Atlas": **"Ortelius is the legitimate, participatory, consented, open civic counterpart to Foundry: one consented event stream that a community uses to reason for itself — decision ontology, audit trail, and a small, exceptionally clean label store in the same object"** [FACT: docs/ORTELIUS_NORTHSTAR.md:309]. The product's core promise, repeated across the design docs, is problem statements **"grounded in data, not vibes"** [FACT: docs/SENSEMAKING_FLOW.md:6-8; docs/audit/DATA_ARCHITECTURE.md:63-68]. So: the intended *outcome* is threefold — (1) upskilled members who ship real civic projects with a team ("finishing the cycle and showcasing what they've built, alongside the group of people they built it with" [FACT: docs/personas.md:41]); (2) a durable, sector-scoped open commons of projects + field research that compounds across cohorts; and (3), at the frontier, a consented, provenance-complete corpus of civic sensemaking whose declared lead buyers are **"a frontier AI lab + local/state political leaders & philanthropists"** — the research artifact (reasoning benchmark + clean corpus + HITL flywheel) and the civic-insight/participatory-legitimacy surface [FACT: docs/ORTELIUS_NORTHSTAR.md:264, owner decision 2026-07-05].

## 2. The product model as built

**Participant journey (BUILT, verified end-to-end).** Register (Google OAuth funnel, scroll-gated Participant Agreement, zip→Local Lab choice) → join a Build Cycle (Open Cycle Agreement ceremony, `cycle_agreements`) → submit problem statements → budget-ballot vote → winners become **pods** (12-person floor) → pods submit solution proposals → second vote → winners become **projects** → weekly **Learning Log** hard gate throughout → showcase/graduation. The 6-phase state machine (`problem_statement → voting → pod_registration → solution_proposal → solution_voting → project_registration`) was audited and made fully drivable on 2026-07-09 — project finalization had literally no caller before then; a 27/27-passing live e2e script (`npm run verify:cycle`) now walks the whole arc [FACT: docs/dev-report-cycle-process.md:17-49,119-128]. PR #302 (merged 2026-07-25) closes the remaining "arc goes silent" seams: an always-on read-only **proposal gallery** at `/cycles/[cycle_id]/proposals`, phase-aware closed states on `/vote`, and an interlude card between voting close and pod registration [FACT: #302, merged 2026-07-25T14:29Z].

**The three-axis org model.** (a) **Sectors** (theme axis): `sectors` + lifecycle `draft→upcoming→active→closing→archived`, ≤1 active + ≤1 upcoming open cycle org-wide, shipped as Phase A in migrations 00048/00049; graduation (Phase C) and commons rollup (Phase D) are still paper [FACT: docs/SECTOR_MODEL.md:3-8,211-229]. (b) **Org cycles** (the org runs its own machinery on itself): `mode='org'` cycles, durable `workstreams` whose quarterly "runs" are ordinary pods, co-lead/contributor/IC ladder, and the staggered Leadership-Log cascade (members Wed, workstream leads Thu, lab leads Fri) [FACT: docs/ORG_CYCLES.md:14-31,129-148; migrations 00060/00069]. (c) **Local Labs** (place axis): metros promoted to the organizational tenancy spine — one shared HQ quarterly open cycle that every lab joins as a sub-cohort (`pods.lab_id` fence, per-lab ballots and pod caps), labs run their own internal org cycles, lab membership gates cycle registration [FACT: docs/LOCAL_LABS.md:8-22,54-73; migrations 00062/00067/00068]. Labs are deliberately **orthogonal to sectors** — "theme vs. place; permanent vs. per-cohort" [FACT: docs/LOCAL_LABS.md:18-22]. The lab tier got a full self-service ratification on 2026-07-11: leads create/run their own org cycles, finalize projects, curate their lab's problem statements — owner rationale quoted: "OLOS is meant to be an open source project that all Labs are contributing to… HQ is meant to be a lean AI-native startup" [FACT: docs/PRD-lab-lead-ux.md:285-297, Decisions 3/6/10].

**Social + measurement layers.** The social layer went from "design ahead of the data" (2026-07-07 audit: 0 feed rows, 58/64 members with no role intents [FACT: docs/audit/SOCIAL_LAYER_ANALYSIS.md:19-42,332-342]) to a real feature set in July: posts/likes/comments/follows (migrations 00072–00077), a **feed-first mobile dashboard** (PR #284, 2026-07-18), a `/network` surface, and a deterministic **pod activity feed** (PR #300, 2026-07-22) [FACT: git log origin/dev aa822f9, b1abda1]. The measurement layer is the Learning Log (replaced Pulse; hard weekly gate, milestone variants), just upgraded to a **nine-item "v2" instrument** for open-cycle logs plus a baseline log (migrations 00087/00091, PR #265) [FACT: 115815e; supabase/migrations/00091]. The public face is a DB-driven CMS (events/resources/metros, Luma sync, stories/spotlights, `/board`) with the Squarespace marketing site captured into `docs/marketing-site/` for sunset onto OLOS [FACT: issue #182; docs/marketing-site/README.md:1-12]. Production is live: dev→main cutover 2026-07-11 ("Release: promote dev → main (production cutover)" fa739eb) [FACT: fa739eb].

## 3. The Ortelius / sensemaking arc

This is the load-bearing ambition, and it has a deliberately layered architecture: a **floor** ("a hunch, and the evidence for or against it") and a **ceiling** (consent-governed, bitemporal, provenance-complete "counter-Foundry" decision substrate) [FACT: docs/ORTELIUS_NORTHSTAR.md:96-101; docs/SENSEMAKING_FLOW.md:12-33]. The member-facing engine is: **distribute a public field survey → BYO-LLM extraction (deterministic prompt, member's own model, upload result — no in-app LLM by rule) → collective swipe (signal/noise) → hypothesis canvas with signed `supports/complicates/refutes` edges → Paradox Sprint (cluster, second, vote) → pods born carrying their evidence** [FACT: docs/SENSEMAKING_FLOW.md:36-54,108-183]. The theory stack (Dorst Frame Innovation, Community Capitals, Actor-Network Theory) is fixed; graph semantics live in `ORTELIUS_KNOWLEDGE_GRAPH.md` (Postgres-native: FKs + one polymorphic `asset_links` edge table + `content_embeddings` — "no graph database" [FACT: docs/audit/DATA_ARCHITECTURE.md:165-173]). Key owner decisions (2026-07-05): every survey response is a graph node with curation as a temporal overlay; consent is **bundled** at submission ("projects that leverage AI hosted by The Labs" — attorney review still pending); lead buyers are a frontier lab + civic leaders [FACT: docs/ORTELIUS_NORTHSTAR.md:261-266].

**What exists vs. planned:** Only the first slice is code. `field_surveys`/`survey_responses` shipped (00053), with a survey question builder (00061), one-survey-per-cycle + cycle linkage (00089), a backfill of the legacy Civics & Elections Google-Form responses (00090), a public `/survey/[slug]` intake and a `/survey/[slug]/results` page [FACT: supabase/migrations/00053,00061,00089,00090; app/(survey)/survey/[slug]/page.tsx]. **Nothing else from the spine exists** — no `sensemaking_sessions`, `problem_situations`, `asset_links`, `content_embeddings`, extracts, or swipe mechanics in any migration [FACT: grep of supabase/migrations/ — only 00053 mentions these names, in comments].

**The Triangulator is the canvas, and it is a second repo.** The Frame-Creation canvas lives in `TheUpskillingLabs/triangles` (contents UNVERIFIED — outside this session's access). OLOS-side evidence: the unmerged **Sensemaker integration brief** (PR #185, branch `claude/sensemaker-brief`, 2026-07-06) is "the concrete plan for porting the Triangulator… into the OLOS experience as the Data Sensemaker" — 547KB of dependency-free vanilla JS, ~70% shared design DNA, reskin-to-paper, canvas *earned* via extract→upload→swipe, proposed `sources`/`extracts`/`extract_sorts` tables and a WS-A/B/C agent-team build order [FACT: git show origin/claude/sensemaker-brief:docs/SENSEMAKER_INTEGRATION.md; f7c9c1d]. That port has sat unmerged for ~3 weeks. Meanwhile PR #302 shipped a *lighter coupling instead*: problem statements gain an optional `repo_url` pointing at "Triangulator working folders (GitHub repos)," and every survey observation gets a stable `#r-<id>` anchor "that the Triangulator's pre-loaded extract cards cite (see TheUpskillingLabs/triangles#72)" [FACT: #302 body; triangles#72 UNVERIFIED]. [INFER: high — two coexisting artifacts] The team is running sensemaking *outside* OLOS for the current cohort: members work in per-team Triangulator GitHub repos seeded with extract cards that deep-link back to OLOS survey rows, while the full in-app Data Sensemaker port remains the documented Phase-6 plan. This is an interim bridge, not an abandonment — but which path wins is the biggest open architecture fork in the repo.

## 5. What the last ~3 weeks reveal about direction

The July-early flood built *structure* (labs, org cycles, roles, social). Since ~07-14 the center of gravity moved to **operating the live Civics & Elections cycle and wiring the sensemaking loop into it**:

1. **Survey → cycle integration became real product, not docs.** One survey per cycle enforced (00089), admin linkage UI, the dashboard survey card/strip, "Explore the answers so far," backfill of the legacy Google-Form responses (00090), and participant-visible results with citable anchors [#302]. [INFER: high] This is a team serving live users weekly — alpha operations, not greenfield build.
4. **Instrument seriousness:** Learning Log v2's nine-item instrument and the baseline log — the measurement layer being tuned for longitudinal data quality [FACT: 115815e, 098b46c].
